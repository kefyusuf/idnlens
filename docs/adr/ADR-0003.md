# ADR-0003 — Pin standard data and provenance

- **Status:** Accepted
- **Date:** 2026-10-15
- **Owner:** Project maintainer (review approval recorded by merging ADR proposal)
- **Scope:** M0/M1

## Context

Unicode security mappings and the Public Suffix List change over time. Unpinned data makes security regressions impossible to reproduce and may introduce licensing problems.

## Decision

Record exact UTS #39 confusables/scripts, UTS #46/IDNA implementation, and PSL snapshot versions or hashes, source URLs, build transforms and licenses. Bundle or lock versions; changes require a reviewed PR and regression tests. No runtime downloads in M0/M1.

## Alternatives considered

Download latest mappings at runtime; rely on implicit runtime Unicode tables; maintain an ad-hoc character list.

## Consequences

Reproducibility and auditability in exchange for update maintenance and a known data-freshness tradeoff.

## Evidence required for acceptance

An implementation-time docs/DEPENDENCIES.md records sources, versions, licenses and SHA-256 values, backed by conformance and PSL fixture tests.

## Acceptance scope and remaining implementation evidence

**Design acceptance does not certify implementation.** The policy to pin standards data, transformations and checksums is accepted for future M0 work. Gate 0 source evidence records Unicode 18.0.0 / UTS #39 Revision 34, `tr46@7.0.0` / UTS #46 Revision 36, and PSL snapshot `publicsuffix/list@3929462652695bad04f0a27afb600974014a3c8b`. Immutable source references and npm lockfile digests remain the initial review baseline, not automatic permission to redistribute derived data.

Pinned source-file hashes are **not** proof that M0 UTS #39 confusable/script transformations or conformance fixtures have been implemented. The upstream PSL generator was not replayed: the source Gitlink and packaged trie identity were verified. This known limit is acceptable for reviewing the *candidate*, but must be revisited if IDNLens rebuilds or modifies the trie, changes snapshot/version, or claims full source-to-output reproducibility.

M0 must provide versioned data inputs, reviewed transforms, deterministic fixtures and final third-party notices for any distributed derived data. No runtime downloads. Later package/data changes require a distinct reviewed PR.

## Decision gate

**Design policy accepted by the maintainer through the reviewed ADR PR merge.** M0 start, implementation conformance and public distribution remain subject to their separate gates.
