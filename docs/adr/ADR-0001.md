# ADR-0001 — Build a deterministic offline core first

- **Status:** Proposed
- **Date:** 2026-10-15
- **Owner:** Maintainer (pending review)
- **Scope:** M0

## Context

The main uncertainty is correct Unicode identification, not UI construction. Starting with a browser adapter would conflate detection defects with browser lifecycle defects.

## Decision

Build a synchronous, pure TypeScript analyzeDomain operation. Accept a hostname and explicitly injected catalog/versioned datasets. Do not require a network, database, browser API, account, or AI service. Wrap it in a browser adapter only after M0 verification.

## Alternatives considered

Build UI and core concurrently (faster demo but hides algorithmic issues); backend reputation API (privacy and operational scope); general-purpose security SDK (opaque behavior and unwanted abstractions).

## Consequences

Portable, deterministic, auditable and testable. User-facing browser warnings must wait for M1.

## Evidence required for acceptance

Identical inputs and pinned datasets reproduce identical results; tests and dependency inspection show no runtime network calls.

## Decision gate

This ADR remains proposed. Acceptance requires the evidence and scope review described in the roadmap. Do not treat this document as implemented behavior.
