# ADR-0002 — Standards-based normalization and registrable-domain identity

- **Status:** Accepted
- **Date:** 2026-10-15
- **Owner:** Project maintainer (review approval recorded by merging ADR proposal)
- **Scope:** M0

## Context

Unicode, Punycode, subdomains, compound suffixes and registry-specific validity constraints make string splitting or substring matching unsafe.

## Decision

The core accepts a hostname, not a complete URL. The browser adapter parses navigation URLs and extracts hostname. Pin and test the IDNA/UTS #46 implementation; resolve registrable domains using a pinned Public Suffix List with an explicit private-suffix policy. IPs, localhost, malformed and ambiguous hosts return UNSUPPORTED.

## Alternatives considered

Manual splitting of hostname labels; raw Unicode comparison; passing complete URLs into the core.

## Consequences

Correct identity boundaries and no path/query data in the core. Data versioning and private PSL policy need explicit decisions.

## Evidence required for acceptance

Tests cover example.co.uk, nested domains, A-labels, case normalization, private suffixes, userinfo in URLs, and malformed hostnames.

## Acceptance scope and remaining implementation evidence

**Design acceptance does not certify implementation.** This decision approves the intended hostname-only and registrable-domain identity boundary. The Gate 0 candidates are `tr46@7.0.0` with strict, nontransitional UTS #46 behavior and `tldts@7.4.18` with explicit ICANN and PRIVATE suffix treatment. Source data and npm package integrity are pinned in the Gate 0 evidence. This is **not blanket production dependency or redistribution approval**.

M0-01 must prove malformed/overlong/IP/localhost/URL rejection and Unicode/A-label strict normalization; M0-02 must prove known/unknown/public/private PSL suffix handling and nested domain boundaries. `UNSUPPORTED` is not `NO_INDICATOR` or `SAFE`. The broader Unicode confusable detector and catalog are separate M0 work.

## Decision gate

**Design policy accepted by the maintainer through the reviewed ADR PR merge.** Gate 0 closure and separate M0-01 authorization are required before implementing this policy; source-data notices and final package distribution permissions remain independently blocked.
